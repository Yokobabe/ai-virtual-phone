# 身份隔离接入与回归

分支：`feat/imessage-private-chat`。改写前检查点：`7ab09a5`；基础仓库检查点：`a048141`。本轮接入现有应用，不采用旧审计中“最后身份删空”的界面方案：用户确认的是生成一张全新的默认身份卡。

## 已接入

- 全局身份切换整部手机；编辑姓名/年龄保留唯一 ID，新身份使用 UUID，兼容局域网 HTTP。最后一张删除后生成新 ID 的默认身份。
- KV、localStorage、各业务 IndexedDB 按身份分区；旧数据留在原全局身份的命名空间，新身份不会复制旧进度。角色档案、安装包、预设/世界书/正则、API 资源与桌面外观共享。
- 配置绑定按当前 user 的 char/app 保存，解析身份始终服从全局；角色专绑是共享的多选权限名单。空名单全部开放，删除身份后清除名单引用。
- 应用与引擎角色入口使用可互动角色列表，聊天/群聊/第三方角色动作再次检查权限；群聊允许非好友，但每次生成检查现有成员权限。
- 切换先建立本地恢复点，暂停新请求/定时派发、撤销旧云预约与订阅，然后中止请求、冻结旧页面并重载。拒收其他身份或旧版本的云端回传。取消旧追发/朋友圈/预约队列，冷场重连等待该身份重新参与，不补发切走期间的积压。
- 删除专用流程清理目标身份的数据库、KV、localStorage、私人媒体及恢复点副本；保留其他身份与共享角色/主题的引用。部分删除失败保持封存，可重试，不解封写入。
- 普通数据导出/清理仅访问当前身份私有数据与被明确选择的共享资源；身份生命周期元数据不走普通清库。身份卡导入合并目录，不能通过覆盖数组删除当前身份。模型本地数据工具只读取当前身份的人设。
- 第三方 SDK 存档/用户/角色调用由宿主转换到当前身份；旧 HTML localStorage 在 iframe 中透明映射到当前身份的该应用存档。组合工具的 window/localStorage/IndexedDB/KV 查询入口同步适配。
- 红包新增按 userId 的领取记录，旧名字作为历史别名兼容；改名不会因昵称变化重复领红包。UI 沿用现有 Apple 设置卡和选择面板。

主要文件：`lib/identity-{runtime,lifecycle,access,db-guard,recovery,media-cleanup}.ts`、`lib/kv-db.ts`、业务数据库/角色选择入口、`components/settings/{binding-manager,user-identity}.tsx`、`components/app-market/custom-app-runner.tsx`、聊天/模型/推送模块、数据管理与本地数据工具。恢复入口：`/identity-recovery`。

## 部署与边界

- 3003 原端口原项目已启动，未切共享分支。真实用户浏览器数据未清除；测试用独立临时浏览器。
- 云端现实桥的非回复动作补上身份元数据，已更新源码和公开部署包，未替用户部署 Supabase。旧云端包无法提供完整新协议；客户端会拒绝无归属的旧回传。
- 切换会暂停个人云定时服务/撤销当前设备订阅；需要为当前身份重新启用离线服务。真实网络失败会阻止切换并显示错误。已送达系统的通知不能撤回。
- 第三方使用宿主 SDK 和常见 localStorage 方法已验证；绕过宿主访问外部服务器的数据不属于本地分区。未执行集市每一个应用，也不声明任意第三方代码都自动兼容。
- 其他窗口尚未提交的像素世界等实验文件不是本轮集成范围；不能把这些原始直接存储实验当成已验证的身份应用。
- 恢复点在此浏览器本地；删身份会同步删其恢复副本。代码回退不恢复被删除的数据；在改写代码前，可先使用恢复入口还原完整本地数据。

## 手机验收

1. 刷新 3003，在配置绑定的“当前用户身份”选另一张，检查聊天、记忆、栖所、钱包/订单为空或属于该身份；切回检查原记录。
2. 角色专绑选 A：B 在角色库仍能看到档案，应用不能选它；取消专绑后两者可用，各自历史不合并。群聊测试一个非好友可互动角色。
3. 用新建的测试身份验证改名、删除与最后默认卡；不用原身份做破坏性验收。
