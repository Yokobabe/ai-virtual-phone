# 身份隔离工程可行性最终核对

- 基准 feat/imessage-private-chat / e57d3db；需求为最终方案校验及工程协作规范，未授权本轮启动功能实施。
- 可行：共享基础档案/配置资源，私人数据 userId 归属，角色互动与绑定 userId+characterId，群及应用存档带 userId；读写检索、缓存、删除与后台任务统一范围。不是靠模型遵守身份实现隔离。
- 接口适配：宿主创建不可由应用覆盖的身份上下文，SDK user/db/AI/角色互动接口使用该上下文；切换销毁旧应用实例和任务授权，晚结果校验上下文版本与身份存活。应用名单与安装包共享，存档按身份分开。
- 实样证据：前轮公开 Bubble/Char动物园主要经过 SDK；2048 直接 localStorage。宿主 runner 的 db dispatch 是集中适配入口；host-api 的身份解析也必须统一。需要覆盖 UI runner 与后台 tool runtime 两条路径。
- 自存储应用：sandbox 本地存储适配必须实测，不能仅凭源代码替换 user 文本或只包装 AiPhone.db；直接浏览器存储、外部服务器及自带身份系统不是无条件兼容承诺。
- 生命周期：切走静默；删除封锁写入和撤销云任务后清理全部私人数据，保留其他身份/共享资源。删除当前身份选择存活身份，最后删除进入无身份。名单删空开放全部。
- 迁移：旧数据与单角色配置锁定迁移前全局身份，持久化检查点避免部分失败；共享元数据排除私人状态，备份/恢复/清理加入身份范围。
- 验收门槛：A/B同角色全链路数据对照；改名同名；群非好友与权限变化；切换中生成/支付/通话；后台静默；多标签；删除当前/最后及失败重试；迁移恢复；SDK实样应用及直存储样本。
- 结论：架构可行，无产品规则矛盾；现有功能尚未实现隔离，不能将设计审查视为运行验收，不能保证所有第三方应用无修改兼容。
