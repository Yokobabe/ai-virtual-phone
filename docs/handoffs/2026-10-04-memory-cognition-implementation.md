# 记忆认知与横幅入口 · 第一版实现

2026-10-04；分支 `feat/imessage-private-chat`；基准与回退检查点 `c3cd2d3`（已包含身份隔离）。本轮未 commit、push 或部署；保留其他窗口的所有未提交修改。

## 授权与交付范围

用户授权实施记忆升级，并确认参考图用于选中角色后的记忆库入口。保留短期原生时间线、长期、核心与向量召回；并列新增未了、镜子、凝视。没有修改身份切换整页刷新、迁移手记或实施其他待办。

入口采用居中头像与名字、淡蓝灰背景、粉色文字、左文右图的六张横幅卡片。图片取角色自己的头像/头像历史，不复制参考图画师作品。适配窄屏、系统日夜；返回及进入栏目重置滚动，避免继承入口下半页位置。共同经历作为短期内的筛选入口保留。

## 数据与生命周期

- 记忆数据库升级至 v4，新增 `cognition` store，以 characterId 为键；数据库由现有 identity runtime 按 userId 分库。角色档案仍共享，关系认知与记忆私有。
- 长期摘要与认知在同一个 IDB 事务写入。认知 KV 仅为同步注入缓存，权威记录在 IDB；不把整份认知重复塞进每条摘要。历史高版本备份缺少新 store 时继续升级补齐。
- 镜子包含人物理解、最近情绪、背景心境；凝视为角色对用户和关系的主观认识。每段有更新时间及真实事件 ID、来源、时间、原话节选。空更新保留原认知，引用未知事件/事项、结构错误或截断均不入库、不推进游标。
- 未了按稳定事项 ID 增量更新；约定、计划、愿望、未解矛盾分开。完成/取消保留记录但退出催办。用户可标完成、取消、重新开启，不额外调用模型。生成过程中身份/权限或认知被修改时，取消过时结果，保留修改。
- 长期保留每批事件引用与原话节选；原生原文不删除。核心更新合并已有内容，已被纳入新摘要的旧核心标为历史，不再作为当前核心注入；历史仍可查看，用户编辑历史核心会重新激活。
- 数据管理记忆模块包含新增状态、召回信息及分批游标前缀；原有整库导出同时覆盖新增 cognition store。未在真实用户备份上试验恢复。

## 模型实际输入路径

1. `lib/memory-summarizer.ts` 的一次总结请求：system 使用 `lib/memory-cognition.ts` 的 `MEMORY_COGNITION_PROTOCOL`；user 使用用户现有总结模板替换 char/时间/事件，并补充角色人设、表达习惯、当前用户身份及已有认知/相关事项。模型返回 JSON；只把 summary 字段保存为长期正文，其余字段保存为认知状态。不将用户说明页注入。
2. `lib/llm-prompt-assembler.ts` 单角色路径在默认/第三方预设均追加一次 `memory_cognition` system 消息：`CHARACTER_EMOTION_GUIDANCE` 加当前角色的有预算认知。群路径按成员分别附认知、共用总预算，标记各自知情。设置关闭认知后不附加。现有使用公共 assembler 的线上、线下、剧情、朋友圈、查手机、访谈等和 SDK 角色生成调用随之接入。
3. 注入认知为模型扮演依据，不自动改角色基础档案、不代替角色强制行动。短时情绪超过 6 小时不作为“最近情绪”附加；持续心境附来源时间，由新事件和人设决定演绎。认知数据仍随总结间隔更新，不是每条消息增加额外情绪分析请求。
4. 群成员的私有认知仅标为该成员知晓；多角色由同一模型扮演，知情边界仍需要模型遵循。现有群入群前历史、无摘要剧情投影等原生时间线限制尚未全面重写，本轮不宣称跨应用原文收集已无缺口。

## 成本控制与召回

- 复用同一次记忆总结更新镜子/凝视/情绪/未了，无独立四次请求；查看页面不调用模型。核心提炼沿用原有独立间隔。
- 总结事件正文每批约 12k 估算 token；人设、用户简介、旧认知另有长度/预算限制。长历史按时间分批，并记录待续游标。时间相同的多条事件用来源 ID 继续处理，不被时间水位线跳过；重新整理同一批用稳定摘要 ID，避免重复入库。计数保留生成期间新增事件。
- 旧三层预算保留；相关长期召回另有默认 1800 token / 8 条上限。认知默认 800 token、最多 3 个未了事项；群成员分摊该预算。可在记忆设置中调整。
- 多条记忆且已配置有效向量模型/存在已向量化内容时，结合语义和关键词排序，不再等 100k 预算耗尽。未向量化记忆仍参与关键词检索；没有向量或失败则降级。仅一条记忆不额外请求查询向量。
- 同身份、同模型、同话题的查询向量短缓存 5 分钟/16 项；失败不缓存，不跨身份复用。
- 镜子显示最近一次长期召回方式、候选/命中条数、正文 token 估算。它不等于整次请求用量或账单；不伪造真实模型 usage。

## 用户验收

原来的 3003 地址 → 资源库 → 记忆库 → 选角色。先看六卡入口；在镜子或凝视点“整理更新”（需要原有记忆总结 API，有实际事件才整理），核对原话是否支持模型认知；在未了查看事项分类/补充/完成，再聊一轮检查实际演绎。少量历史也可手动整理。真实生成质量、长聊/关系变化的连续性及手机上的材质仍待用户验收；未宣称完全不失忆。
