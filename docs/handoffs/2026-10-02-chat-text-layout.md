# 普通聊天文字：双语配对与自然换行

## 需求与基准

- 用户授权仅优化文字类，双语短词重复英文/漏译和单语异常换行一起处理。
- 分支 `feat/imessage-private-chat`，本轮基准 `2f60500`。此前验收保存点已本地提交但未推送。
- 未改图片、语音、引用动作、转账、特效协议，不强制JSON输出，不新增补译API调用。

## 改动

- `lib/chat-text-layout.ts`：显示层合并普通角色文字单换行，中英文连接分别处理；用户输入不启用。双空行、HTML、显式Markdown硬换行、列表/代码及短多行诗歌保留。不改保存内容/API历史。
- `lib/bilingual-text.ts`：仅文字气泡可选识别原译文相同（大小写/引号差别）的配对；默认解析行为不变，非中文的任意两列仍不视作翻译。
- `components/chat/message-bubble.tsx`：仅普通assistant文字接入显示整理。相同英文不重复展示为译文，标注“未提供中文译文”；emoji不标缺译。
- `styles/imessage26.css`：普通角色文字原译文区域同宽，保留三预设原有色彩、字号和翻译分隔设计。Pinpoint限定修改文字区域，未顺带调整气泡/特效尺寸。
- `lib/bilingual-prompt-defaults.ts`、`lib/chat-engine.ts`：启用在线双语时追加完整原译配对、禁止普通手动折行、短词和称呼按语境翻译、保留反话语气规则；自定义双语提示同样追加。不增加请求次数，不强制API结构化响应。
- `scripts/check-chat-text-layout.cjs`：无真实存储/无模型的helper、组件静态渲染及生产CSS隔离回归。

## 验证

- TypeScript：`tsc --noEmit -p tmp/tsconfig-approved-effects.json` 通过。
- 文字隔离浏览器：320/390/430宽度 × 经典/玻璃/SP，通过同宽、可读宽度、不溢出、普通软换行合并、用户/显式诗歌换行保留、重复英文缺译提示等检查。截图 `tmp/chat-text-layout-check.png` 已查看。
- 3003整页SP回归：`check-chat-sp.cjs` 最终完整通过，包含预设切换、日夜/三宽度、顶底栏、资料卡与翻译无分隔线。首次运行在刷新时报脚本错误并超时，修改停止后重跑通过；未据此认定具体原因。
- 未调用付费模型/TTS，未操作用户浏览器存储；真实模型翻译质量、手机视觉等待用户验收。

## 限制与状态

- 缺译提示不是补译：旧消息不会凭空产生中文；新消息仍依赖模型遵循提示。完全没有分隔符的英文短句仍按普通单语展示，未猜测其是否漏译。
- 纯文本无法绝对区分诗歌与意外折行：短三行以上保守保留，明确分行可用Markdown硬换行或HTML br。
- 显示整理不改变断句发送的原始存储边界；本轮未迁移历史或全部聊天协议。
- 未commit、push、部署；保留其他窗口未提交改动。
