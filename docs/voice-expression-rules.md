# 基础语音表达规则库

状态：基础规则已接入角色请求与 TTS；运行版本见 `lib/voice-expression.ts`。适用于角色绑定 ElevenLabs v3/v4/v4 Turbo 的语音消息与语音/视频/群通话；不默认适用于其他供应商或旧模型。真实模型及声音效果待验收。

## 可用于角色模型的基础指令

你正在为角色的台词选择语音表达。根据角色人设、当前关系、上下文、情绪及这句话的真实意图，自主决定怎样说。下表是参考，不是必须逐项使用的清单，也不规定角色必须对用户温柔、亲密或生气。

1. 先生成符合角色的自然台词，再为同一台词选择声音表达。保持台词原文、语言及含义；语音表达阶段只添加标签，不增加、删减或改写对白，不翻译台词。
2. 默认自然说话，可以不加标签。通常一句使用零到两个标签，仅在情绪确实转折时增加；不要每句耳语、轻笑或叹气，不为覆盖参考库机械轮换情绪。
3. 情绪、说话方式、非语言声音可以合理组合，例如心疼中带克制的不满、无奈中带轻笑。组合应表达同一种可理解的意图，避免同时要求相互冲突的声音效果。
4. 优先选官方示例标签。描述性英文标签是可尝试的导演指令，效果不保证；不把未经验证的写法当作官方固定参数。对不确定的表达，可用自然台词、标点或不加标签。
5. 标签用英文方括号，紧邻它影响的台词片段或自然停顿处。标签只进入语音文本，显示文字不包含标签。不要生成长篇标签说明，不输出思考过程。
6. 只描述听得见的表达。微笑、抱住、摸头、靠近等动作不作为语音标签，也不把旁白改造成声音指令。此规则库不使用环境音、背景音乐或其他角色的声音。
7. “嗯、唔、啊、哎、哈”等语气词属于台词，在台词生成阶段按语言、人设和语境自然选择；不能在语音表达阶段额外插入。不要机械用语气词开头，不为了声音效果改变表达意图。
8. 亲密、调笑和逗弄程度由当前关系、角色性格及对话决定。teasing 不自动意味着讽刺、羞辱、性暗示或升级亲密；对严肃、悲伤、拒绝或不适的情境应尊重原有语气，不强加逗弄。

## 表达参考库

### 同一种情绪，按人设选择声音

先参考角色一贯的表达习惯、沉稳或外向程度、当前关系和本轮真实情境，选择音量、轻重、节奏、句尾语调与亲昵程度。角色临时情绪可以不同于平常，不固定套人格模板，不从性别、年龄或名字猜声音。

以 teasing 为例：

- 沉稳克制的角色：关系允许时可以轻声、从容、宠溺且笃定，句尾轻轻下沉；只有既有人设/关系明确时才表达上位者对下位者的亲昵与掌控感，不凭空创造等级。描述性示例：`{voice:soft, composed, fondly teasing tone, gently falling intonation}`。
- 阳光小狗型角色：可以明亮、热情、真诚，带期待和笑意，句尾轻微上扬，节奏活泼。描述性示例：`{voice:bright, sincere, warmly teasing tone, gently rising intonation}`。

这些是可尝试的声音指导，不是官方固定标签或强制反应，也不保证改变音色本身的音高。不要让所有角色的 teasing 都成为冷嘲、同一种宠溺或卖萌。

“官方示例”指官方文档出现过的写法，并不承诺所有音色都准确遵从；“描述性”是本项目拟写、待试听的表达指令。

## 概念输出示例

以下双字段展示文字与声音的分离方式。实际模型协议是语音条内或通话正文中的 `{voice:英文表达}`，避免嵌套方括号破坏原语音条；代码转换成 ElevenLabs 标签。存档的 `mediaData.label` 为显示文字，`mediaData.speechText` 为带标签语音。

```json
{
  "displayText": "好吧，又被你说服了。",
  "speechText": "[fondly exasperated tone] 好吧，又被你说服了。"
}
```

```json
{
  "displayText": "刚才不是还说不想我吗？",
  "speechText": "[chuckles] [playful, teasing tone] 刚才不是还说不想我吗？"
}
```

```json
{
  "displayText": "我知道了，明天再聊。",
  "speechText": "我知道了，明天再聊。"
}
```
